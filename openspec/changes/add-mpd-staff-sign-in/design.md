## Context

SendRec already implements recording, uploads, media processing, players and OIDC. Reuse them. `internal/sso/handler_oidc.go` currently discovers workspace SSO through an existing user membership, auto-links by email, and sends an access token in a redirect query. Native recording routes accept SendRec JWTs; API keys only cover video listing. These are the integration points to adapt.

## Goals / Non-Goals

Make individual MPD identities work in the standalone recorder and expose the same recording backend to a future Staff OS client. Keep patient association, clinical authorization and viewing status in mpd-api. Do not create Staff OS screens, embed the whole application, rebuild the recorder or accept shared owner credentials for integrations.

## Decisions

1. Use the matching environment's staff Cognito pool and a separate SendRec confidential app client. Reuse OIDC discovery with authorization code, state, nonce and PKCE. Bind callback, state, nonce and verifier to a short server-side login transaction. Secrets stay in Secrets Manager and are injected into the server. Staging never authenticates against the production pool. Callback redirects carry only a short one-use handoff code, never a bearer token. Redeem through a same-origin POST and use the existing secure refresh-cookie pattern.
2. Add an MPD login entry that does not require a local user first. After Cognito verification, call mpd-api `GET /api/v1/staff/video-access` with that person's access token. Provision the local user and managed workspace membership atomically only if access is granted. Link by issuer plus Cognito sub and store authoritative staffId/tenantId separately. Email and name are display attributes. Existing accounts, including the evaluation owner, require an explicit audited linking operation; email equality alone cannot transfer ownership. Handle concurrent first logins with unique identity constraints.
3. Add `POST /api/auth/mpd/session` for future clients using an approved Cognito staff access token. Validate signature, issuer, token_use=access, expiry and client_id against the approved client list; do not require an ID-token aud field on an access token, then run the same MPD access check and provisioning path. The native OIDC callback and this endpoint issue the same managed SendRec session. A cross-origin client uses an in-memory access token and renews by presenting its current Cognito token; it gets no long-lived cross-site refresh cookie. Configure exact allowed origins. A synthetic client proves this path without building Staff OS.
4. Every managed route, including API-key listing, personal-context requests, mutations, session refresh and workspace administration, must check the managed session and MPD-derived capability. Deny independent local password/social-login paths for managed staff. Lock managed workspace SSO configuration, SCIM-token issuance and SCIM user/membership create/update/delete to the deployment-controlled integration. Existing SCIM tokens cannot provision, relink by email or change managed accounts. Local workspace administrators cannot substitute an identity provider or bypass the MPD access check. Derive local viewer/member/admin roles from read, record-or-manageOwn and manageWorkspace respectively, but use the capability response as the final gate. The response includes record, read, manageOwn, manageWorkspace and readPassword. record permits creation/upload; manageOwn permits mutations of the caller's own media; manageWorkspace permits media mutations across the bound workspace. Neither implies account retirement or retention-policy changes. read permits authorized workspace reads and readPassword gates password disclosure. Adapt existing RequireWriter checks for managed routes so they cannot preempt or replace the current capability/ownership check. Test every action against ownership and its exact capability, including record-only and manageOwn-only synthetic responses, not only projected roles. Do not let a local admin or X-Organization-Id header expand rights. Disable self-service account/workspace deletion and retention_days changes for managed staff/workspaces, including API calls and personal settings. Offboarding revokes access while retaining workspace media. Operator retirement requires a separately reviewed procedure that preserves deletion events and tombstones. Public watch/embed access retains its separate password policy and never grants management access.
5. Cache access only until the producer's validUntil, no longer than 30 seconds. Cap native access sessions at 15 minutes and at the valid Cognito token lifetime. Native Cognito refresh credentials stay encrypted server-side; renewing a SendRec session revalidates Cognito and MPD access. Future-client sessions cannot outlive their submitted Cognito token. Ended membership or lost rights must stop new managed requests within 60 seconds. Expired checks during an outage fail closed. New signed playback/download GET URLs last at most 5 minutes; upload PUT URLs retain their existing bounded upload lifetime and are issued or renewed per screen/webcam upload after authorization, so sequential uploads do not expire before use; previously downloaded bytes remain outside revocation. Watch, embed, shared-playlist and authenticated library/detail players renew URLs before expiry through a same-origin endpoint that repeats publication, password and managed-session checks. Preserve playback position and paused state when replacing the URL; retry one expired-signature Range request through renewal. Refused renewal stops playback. Downloads can obtain a fresh authorized URL before a resumed request; already running S3 requests follow storage expiry semantics. Renewal never extends access to a new unauthorized request. Verify a recording longer than 15 minutes, a pause across expiry and seeking after expiry; a short URL alone is not sufficient.
6. Supply a small server-only adapter API: `GET /api/integrations/mpd/videos/{videoId}` returns status, ownerStaffId, tenantId, mediaVersion and protected watch/embed references; `GET .../{videoId}/transcript` returns bounded transcript data with mediaVersion and transcriptVersion; `PUT .../{videoId}/password` applies the existing protection mechanism; `PUT .../{videoId}/publication` controls share/watch/embed availability. Managed recordings begin unpublished. Provide a separate authenticated staff-preview operation that checks the current read capability and workspace/ownership policy before issuing short video/version/session-bound preview authorization. It can play unpublished media in an authenticated preview route without publishing it; public watch/embed remain closed. Preview authorization is distinct from the classification-only cookie or public playback proof, and renewal repeats staff checks. Future clients can request the same preview authorization through the existing staff session. The native recorder/library shows Unpublished and disables copy/share until an authorized publish action succeeds with its configured password policy. Expose that action and failures in the standalone UI; do not hand out an unusable link after upload. A permitted staff sharing action or the MPD report adapter can publish; a share token alone cannot bypass this state. Apply password changes before publication. This is generic media access state, not patient metadata. Inventory all token-based and playlist access routes, including /watch/playlist, /embed/playlist, oEmbed/thumbnails, comments, milestone/progress, watch identify/cta-click/verify/download and playlist verify/identify endpoints. Enumerate all registered share-token routes in an access-policy table and test each, including metadata and analytics writes. Every media item must pass publication and its own password policy; playlist tokens cannot bypass per-video checks. Public auxiliary routes must not reveal unpublished metadata or accept unauthenticated playback facts. A dedicated rotated service token permits only these operations for the configured MPD workspace. It cannot log in, record, list staff, delete videos or enter MPD staff routes. Audit it as the MPD service, not a doctor. mpd-api receives its secret through existing environment injection. Restrict media URLs to the configured SendRec origin and signed storage locations; never follow arbitrary response URLs.
7. Reuse existing media endpoints and document their request/response shapes in the integration handoff. Recording bytes still go directly to S3. When MPD revalidation is unavailable or the session expires during recording/upload/finalization, preserve local blobs and resumable upload state in the open client and show reauthenticate/retry. Do not automatically DELETE a take for temporary authorization or network failure. After access returns, revalidate before retrying/finalizing; revoked users cannot publish. Intentional cancellation and expiry cleanup use the durable deletion path. Test an outage longer than the authorization cache during sequential screen/webcam uploads and finalization. No patient identifier or patient metadata field is added to SendRec. Retain a restricted operator recovery path and verify it cannot provision staff or bypass MPD grants silently.

## Risks / Trade-offs

- Independent local sessions could outlive offboarding. Test every existing route/authentication alternative and existing refresh token, not only a new login.
- Upstream workspace limits can block provisioning. Verify configured seat/recording limits against the approved pilot and report a clear capacity error; do not pretend a billing plan changed.
- A managed service credential is powerful within its small scope. Store only its verifier in SendRec, rotate with bounded overlap, redact requests and disable immediately on retirement.

## Migration Plan

Depends on mpd-api `add-sendrec-staff-access`. Add schema and disabled configuration first. Activate a new empty managed workspace for the initial pilot; keep evaluation media outside it. Existing personal/workspace videos cannot enter managed scope through an identity link or header change. Explicitly reject POST /api/videos/{id}/transfer into or out of a managed workspace; the reviewed operator adoption procedure is the only route across that boundary. A later explicit media adoption requires verified owner/tenant binding, unpublished state, playlist/access audit and expiry of previously issued URLs before activation. Refuse activation or adoption while any owner is unlinked. Configure a synthetic Cognito client and workspace, prove login/denial/offboarding, then enable standalone login. Link the evaluation owner only through a verified operator action. Rollback disables both MPD entry points and revokes their sessions while preserving recordings and identity links. Do not turn public registration back on. Production activation belongs to `prepare-production-video-service`.
