# Video encoding: frames, probes and tests

- Every playback encode (`normalize.go`, `transcode.go`, `trim.go` in both branches, `remove_segments.go`) takes an `outputFrame` from `output_frame.go`: first-frame size fitted in 1920×1080, then `scale=W:H:…decrease:force_divisible_by=2,pad=W:H:…`. A zero frame falls back to per-frame `min(1920,iw)` scaling. `composite.go` still scales per frame.
- ffprobe `stream=width,height` is the stored size; ffmpeg autorotates before `-vf`. `probeVideoProperties` reads `stream_side_data=rotation` (`side_data_list[].rotation`, reported by ffprobe 6.1 in the image and 9 locally; neither reports the legacy `rotate` tag) and `probeOutputFrame` swaps the sides for a quarter turn. Make a rotated fixture with `ffmpeg -display_rotation 90 -i in.mp4 -c copy out.mp4` (ffmpeg ≥ 6; `-metadata:s:v rotate=90` writes nothing on 9).
- `force_original_aspect_ratio=decrease` with `force_divisible_by` rounds down in ffmpeg, so the scaled frame never exceeds the pad (checked on ffmpeg 9.0.2 with odd sizes).
- `needsNormalization()` re-encodes `avc3` MP4s (ffprobe `codec_tag_string`): in-band parameter sets mean the header size holds only for the first frame.
- Test stubs share one signature across `transcodeToMP4` and `transcodeToIOSCompatible` (`edit_commit_db_test.go`, `source_key_db_test.go`); keep the four encoder vars alike and probe inside them rather than widening their signatures.
- A mid-stream resize fixture without a browser: two `testsrc2` MPEG-TS segments of different sizes concatenated bytewise (`output_frame_test.go`). The joined TS restarts its clock at the join, so remove-segments output is shorter than the cut suggests. One output size does not prove the fit (autoscale gives one size too): `topRowsLuma` reads the top 40 rows of a frame as gray rawvideo; a letterbox bar reads 0, squeezed `testsrc2` picture about 118.
- ffprobe frame sizes: `ffprobe -v error -select_streams v:0 -show_entries frame=width,height -of csv=p=0 f.mp4 | sort | uniq -c`.
- `go test ./...` needs `web/dist`: `cd web && pnpm install --frozen-lockfile && pnpm build` (about 2 min). The video package alone takes ~25 s and runs ffmpeg when installed.
- Encode budget: `encodeTimeout(duration)` = `perJobTimeout` 10 min + 2×duration (capped at 110 min extra) for every encode (composite, WebM conversion, normalise, trim, remove-segments), from the worker, `EnqueueJob` and the edit handlers alike; `resetStuckProcessing` gives every row in processing the same 2×duration allowance on top of its 15 min; `MAX_CONCURRENT_ENCODES=1` in ECS, 2 vCPU Fargate tasks; the worker ticks every 2 min and retries up to 5 attempts. `deadlineDB` and `deadlineStorage` in `transcode_test.go` read the job context's deadline.
